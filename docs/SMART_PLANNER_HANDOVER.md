## สิ่งที่ปรับในทุกหน้า

| หน้า | การปรับปรุง |
|---|---|
| ริงเดี่ยว | จัดอันดับจาก Suitability, Lead, Gap และทางเลือกริงถัดไป แสดงเหตุผลและคีย์ทางเลือก ใช้ความยาว 1.2/1.4 m ตามชนิดคีย์จริง |
| วางแผนต่อเนื่อง | ค้นหาล่วงหน้า 1–3 ริง ตรวจชนิดที่อนุญาต ผลรวมระยะตามความยาวจริง เลือกริงจากกราฟ/ตาราง และกรองคำเตือน |
| แนวอุโมงค์ | ใช้ข้อมูลแนวที่บันทึก ตรวจ DTA, Lead, Gap และ Suitability ทั้งสองวิธีเลือกคีย์ เปรียบเทียบยอดคีย์ที่ได้กับ Ratio เป้าหมาย แจ้งผลเก่าเมื่อแก้เงื่อนไข |
| Dashboard | แยกข้อมูลสนาม แผน ตัวอย่าง และข้อมูลเก่าไม่ระบุแหล่ง ไม่ใช้ Lead แทน DTA คลิกกราฟดูริง และเปิดประวัติด้วยตัวกรองตามข้อมูลที่เลือก |
| ประวัติ | ค้นหา กรอง เรียงลำดับ แบ่งหน้า แก้ไข/เลือกลบด้วยตัวตนของริงแทนตำแหน่งแถว กรอกค่าจริงภายหลังได้ และต้องยืนยันแหล่งข้อมูล |
| สารปรับปรุงดิน | Foam/Polymer ตรวจข้อมูลแยกกัน ปฏิเสธตัวหารเป็นศูนย์ เก็บค่าอ้างอิงเปรียบเทียบ และประมาณการปริมาณ Foam/น้ำ/เวลาตามจำนวนริง |
| ข้อมูลหลัก | ตรวจ STA ต่อเนื่อง รัศมี Ratio และชนิดที่อนุญาต เพิ่มเกณฑ์ Gap ร่วมทุกโหมด คำนวณ BOQ จำนวนเต็มโดยยอดรวมไม่ขาด/เกิน คงแท็บแนวดิ่ง ฐานคีย์ เมทริกซ์ และ Taper Simulator |

การแสดงผลใช้เมนูภาษาไทย ธีมสว่าง/มืด ฟอนต์และขนาดข้อความปรับได้ ระยะห่างแบบอ่านสบาย/กระชับ และเมนูมือถือ ป้ายสถานะมีข้อความและสัญลักษณ์ กราฟและตารางอ่านตัวเลขได้ชัดเจน หน้าต่างตั้งค่ารองรับ Tab และ Escape

## ข้อมูลและการบันทึก

- ข้อมูลสนามเก็บใน `tbm_ring_logs` ส่วนแผนอยู่ใน `tbm_saved_plans` การบันทึกแผนไม่เพิ่มยอดติดตั้งจริง
- ย้ายแผนเก่าที่ระบุได้จากหมายเหตุ โดยรักษาข้อมูลต้นฉบับไว้ใน `tbm_ring_logs_before_smart_ui` ก่อนบันทึกครั้งแรก
- ข้อมูลตัวอย่างมาตรฐานถูกระบุเป็น sample ข้อมูลเดิมที่ไม่มีหลักฐานแหล่งข้อมูลเป็น legacy ไม่ถือว่าเป็นค่าตรวจสนามโดยอัตโนมัติ
- ปรับน้ำหนักเฉพาะข้อมูลที่ระบุเป็น measured และมี H/V Lead ใช้งานได้ จำนวนข้อมูลไม่ใช่เปอร์เซ็นต์ความแม่นยำ
- บันทึกข้อมูลสนามที่เชื่อม Cloud ต้องได้รับผลยืนยันก่อนแจ้งสำเร็จ ค่า Gap 0 และ DTA ที่ไม่มีข้อมูลไม่ถูกแทนด้วยค่าปกติ
- แผนใหม่เก็บในเครื่อง ปุ่มอัปโหลด Cloud ส่งเฉพาะข้อมูลที่ระบุเป็น measured และแนวที่บันทึกไว้
- การดึง Cloud รวมกับข้อมูลในเครื่องตามหมายเลขริง รักษารายการในเครื่องที่ไม่มีในผล Cloud เพื่อไม่ลบข้อมูลโดยการดึงข้อมูลอย่างเดียว
- ปุ่มสำรองข้อมูลส่งออก JSON ของข้อมูลและการตั้งค่า ไม่รวมข้อมูลเชื่อมต่อ Supabase
- CSV รองรับภาษาไทย เครื่องหมายคำพูด จุลภาค และหมายเหตุหลายบรรทัด

## การตรวจที่ทำแล้ว

`npm run test` ผ่าน 12 รายการ ครอบคลุม Gap 0, ค่าขาดหาย, ขอบเขตเตือน/วิกฤต, DTA แยกจาก Lead, Transition Matrix, ความยาวเซ็กเมนต์, ลำดับแผน, BOQ, การตัดข้อมูลจำลองออกจากการปรับน้ำหนัก, แนวที่ไม่ต่อเนื่อง, DTA ที่ใช้จัดอันดับตรงกับผลแสดง, Foam/Polymer และ CSV

`npm run lint`, `npm run build` และ `git diff --check` ผ่าน

ลองใช้งานผ่านหน้าเว็บครบ 7 หน้า และแท็บย่อยข้อมูลหลักทั้ง 5 แท็บ ตรวจหน้าจอ 320/390 px และขนาดเดสก์ท็อป แก้การล้นกรอบที่พบ ทดสอบจำนวนริงเป็นศูนย์ ความเร็วเป็นศูนย์ การเปลี่ยนเงื่อนไขแล้วคำนวณใหม่ การเก็บแผน การแก้ไขริงหลังกรอง การยืนยันค่าจริง ธีม ฟอนต์ และคีย์บอร์ด

การลองเก็บ/แก้ไขใช้แผนคาดการณ์ในหน้าทดลอง localhost เท่านั้น ไม่ได้ลบข้อมูลหรือบันทึกข้อมูลสนามจริง และไม่ได้ส่งข้อมูลไป Cloud

## ขอบเขตของผลคำนวณ

- เป็นระบบช่วยเลือกและตรวจแผนแบบกำหนดกฎ สามารถอธิบายเหตุผลได้ ไม่ได้เชื่อมโมเดล AI ภายนอก
- Gap ใช้แบบจำลอง 50 ± 0.30 × Lead ตามค่าตั้งต้น/เกณฑ์ที่ผู้ใช้กำหนด ค่าคาดการณ์ถูกจำกัด 0–100 mm
- Advance เพิ่มการจำลองเยื้อง H/V และมุมคลาดจาก pose ที่ผู้ใช้กรอก พร้อมแนวแก้และตรวจปลายทางแล้ว ดูรายละเอียด/ขอบเขตใน docs/ALIGNMENT_RECOVERY.md ส่วนริงเดี่ยวและแผนต่อเนื่องไม่มีข้อมูลพิกัดสำหรับตรวจ DTA
- Ratio ใช้เป็นเป้าหมายในการจัดอันดับ ไม่ใช่ตัวแก้โจทย์ที่รับประกันจำนวนผลิตตรงทุกชนิด ระบบแสดงยอดที่ต่างจากเป้าหมายก่อนนำไปใช้
- Roll ในหน้าริงเดี่ยวใช้แสดงตำแหน่งวงแหวน ยังไม่หมุนเวกเตอร์ Lead ตาม Roll
- Foam/Polymer คำนวณตามค่าที่กรอก ยังไม่เลือกสูตรสารจากสภาพดินอัตโนมัติ
- การทดสอบยืนยันการทำงานของซอฟต์แวร์และความสอดคล้องของสูตร ไม่ใช่การสอบเทียบกับผลสำรวจหรือรับรองแผนติดตั้ง
- ยังไม่ได้ทดสอบกับ Supabase จริงหรือ schema ของฐานข้อมูลที่ใช้งานอยู่ ผลการตรวจเผยแพร่บันทึกแยกในรายงานส่งมอบ
